Purpose: editorial research inventory for Meaning Layer planning and Core 10 selection.

Scope: audit repository original-language data against the proposed Core 100 candidate list; do not publish as a public list or implement new Meaning Card pages from this document alone.

Source of truth: repository generated original-language term data and generated occurrence data first; documentation second; outside sources only as a last-check aid.

No public numbering: row numbers in this draft are editorial order only and do not create a public ID system.

Phase-exception note: Meaning Layer research is an approved phase exception and does not change CR-90Y or the roadmap phase.

## 1. Purpose
This draft records a verified editorial inventory of 100 Meaning Word candidates, with corrections applied where repository data disagreed with the previous proposal.

## 2. Editorial Definition
Core 100 is not a frequency list. It is a curated set of lemmas that support covenantal, canonical, and cross-testament meaning research.

## 3. Selection Principles
- Importance for canonical reading and covenant flow
- Passage-sensitive meaning rather than single-gloss simplicity
- Real translational movement or semantic range
- Actual repository lemma and occurrence support
- Minimal duplicate synonym load

## 4. Language Balance
- Approved target: Hebrew 61 / Greek 39
- Draft result: Hebrew 61 / Greek 39
- Balance is preserved, but not at the cost of wrong lemma or wrong passage choices.

## 5. Theme Framework
1. Creation and Life / 창조와 생명
2. Covenant and Promise / 언약과 약속
3. Sin and Righteousness / 죄와 의
4. Holiness and Worship / 거룩과 예배
5. Sacrifice and Temple / 제사와 성전
6. Kingdom and Messiah / 왕국과 메시아
7. Word and Revelation / 말씀과 계시
8. Faith and Salvation / 믿음과 구원
9. Spirit and Community / 성령과 공동체
10. Judgment and Completion / 심판과 완성

## 6. Verification Policy
- Verified means lemma, Strong, transliteration, and base passage are aligned with repository data or already completed pilot validation.
- Needs Review means the row is still a valid candidate, but the exact occurrence or final base passage still needs a later pass.
- This draft does not assign public IDs or publish Meaning Card content.

## 7. Status Definitions
- completed: pilot implemented and browser-verified
- selected: recommended Core 10 candidate
- review-needed: valid Core 100 inventory item awaiting deeper editorial pass

## 12. Root-Family Decisions
- `צֶדֶק` and `צְדָקָה` are both retained because they test noun nuance rather than simple duplication.
- `גָּאַל` and `גְּאֻלָה` are both retained because the verb-noun pair helps test redemption language across passage types.
- `שׁוּב` is retained instead of `תְּשׁוּבָה` because the repository strongly supports the verb form as the better meaning card base.
- `כִּפֶּר` is retained as the atonement verb; `כָּפַר` is not used as the Core 100 anchor here.
- `חֵטְא` is retained as the noun; `חָטָא` is deferred as the corresponding verb-family counterpart.
- `פֶּשַׁע` is retained as the noun; the verb-family counterpart is deferred.
- `מוּת` is not used in the Core 100 draft because `מָוֶת` already covers the death noun slot.
